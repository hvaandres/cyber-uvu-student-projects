Before We Start: What Is "The Terminal"?

Almost every step below asks you to "open a terminal and run a command." If you've never done this, here's what that means.

The terminal (also called the command line, shell, or console) is a text-only way to talk to your computer. Instead of clicking icons, you type a command and press Enter.

How to open it:

  • Mac: Press Cmd + Space, type Terminal, press Enter.
  • Windows: Press the Start button, type PowerShell, press Enter.
  • Linux: Press Ctrl + Alt + T.

Important: When you see a command in a black box on this page, type or paste only the command. Lines starting with # are comments for humans — the computer ignores them.

Step 1 — Install JavaScript (Node.js)

1.1 — What is JavaScript?

JavaScript is the programming language our project is written in. It was originally built to run inside web browsers (Chrome, Safari, Firefox) to make web pages interactive — things like dropdown menus, form validation, and pop-ups.

But our project also needs JavaScript to run on the server side — the part that talks to the database and handles logins. Browsers can't do that. So we install a program called Node.js.

Simple analogy: JavaScript is a recipe. A browser is a kitchen that can only cook certain recipes. Node.js is a full professional kitchen installed on your laptop, so you can cook any JavaScript recipe — even ones a browser can't handle.

Common point of confusion: You cannot "install JavaScript" by itself. The language has no installer. When your instructor says "install JavaScript," they mean install Node.js. These are the same task.

1.2 — What is npm, and why do I keep hearing about it?

When you install Node.js, you automatically get a second tool called npm (Node Package Manager). You do not install it separately.

npm is an app store for code. Other developers write useful chunks of code ("packages" or "libraries") and publish them for free. Instead of writing everything yourself, you download theirs.

Real example: Building a web server from scratch is hundreds of lines of tricky code. Instead, you run one command:

npm install express

…and you now have a fully working web server library. That's the whole point of npm.

1.3 — Download and install

Step 1.3a — Go to the official site

Open https://nodejs.org in your browser.

You will see two big green download buttons. Always pick the one labeled "LTS." LTS stands for Long Term Support, which means it is the stable, well-tested version. The other button ("Current") has the newest experimental features and can break things. Beginners should never use it.

Step 1.3b — Run the installer

Find the downloaded file (usually in your Downloads folder) and double-click it.

  • Mac: the file ends in .pkg
  • Windows: the file ends in .msi

Click Next / Continue through every screen and accept all the default settings. Do not change anything. You may be asked for your computer password — that is normal and expected.

Step 1.3c — Close and REOPEN your terminal

This step matters. If a terminal window was already open during installation, it does not know Node.js exists yet. Quit the terminal completely and open a fresh one.

Step 1.3d — Verify it worked

In your new terminal, type this and press Enter:

node --version

Then run this one:

npm --version

What success looks like

You should see version numbers printed, something like:

v22.11.0 10.9.0

The exact numbers will differ from the example and that is completely fine. Seeing any version number means it worked.

If you see "command not found" instead

  1. Fully quit the terminal app (not just close the window) and reopen it.
  2. Restart your computer — this genuinely fixes it most of the time.
  3. Still broken? Post in the course discussion board with a screenshot of what you typed and what you saw.

Step 2 — Install a Database Tool (DBeaver)

2.1 — What is a database?

A database is an organized place where your application permanently stores information — user accounts, passwords, orders, messages, log entries, and so on.

Picture a giant, extremely fast Excel workbook. It has multiple sheets (called tables), each sheet has columns (fields) and rows (records). Unlike Excel, a database can hold millions of rows and find any one of them in a fraction of a second, and many people can safely use it at the same time.

Example: When you log into Canvas, the site takes your username, asks the database "do you have a row with this username?", checks your password, and lets you in. That entire lookup happens in milliseconds across tens of thousands of students.

2.2 — Why do I need a separate tool for it?

The database itself has no screen and no buttons. It's a background program that only understands a language called SQL. To actually see and work with your data, you need a database client — a visual app that connects to the database and shows you the tables.

With a database client you can:

  • ✓Browse every table and see the real data inside it
  • ✓Confirm that your code actually saved the record it claimed to save
  • ✓Write and test SQL queries safely before putting them in your code
  • ✓Manually add, edit, or delete rows while testing
  • ✓Diagnose bugs — is the bug in your code, or is the data itself wrong?

Why this saves you hours: Without a database tool, when a feature breaks you are guessing. With one, you look directly at the table and instantly know whether the data arrived. This is the single most useful debugging skill in this course.

2.3 — Which tool should I use?

Several free tools do this job. Here are the most common ones so you recognize the names:

Tool Works With Cost Notes
DBeaver
(use this one)		 MySQL, PostgreSQL, SQLite, SQL Server, Oracle, and ~80 more Free One tool for every database. Works on Mac, Windows, Linux.

Our recommendation: Install DBeaver Community Edition. It's free forever, connects to any database you'll meet in this course or your career, and all screenshots in this class use it. If you already have one of the others installed and prefer it, that's fine — the concepts are identical.

2.4 — Install DBeaver

Step 2.4a — Download

Go to https://dbeaver.io/download/

Choose Community Edition (the free one) and pick the installer matching your computer. On a Mac, check whether you have an Apple Silicon chip (M1/M2/M3/M4) or an Intel chip — click the Apple menu → About This Mac to find out, then download the matching file.

Step 2.4b — Install and open

Run the installer with all default settings. On Mac, drag the DBeaver icon into your Applications folder. The first time you open it, macOS may warn that it was downloaded from the internet — click Open to continue.

Step 2.4c — Create your first connection

  1. Click the plug icon with a "+" in the top-left toolbar (or use the menu: Database → New Database Connection).
  2. A grid of database logos appears. Pick the one your project uses — most likely PostgreSQL or MySQL. Ask your instructor if you're not sure.
  3. Fill in the connection fields (explained in the table below).
  4. DBeaver will say "Download driver files?" — click Download. This is normal and only happens once per database type.
  5. Click Test Connection in the bottom-left corner.
  6. If you see a green "Connected" message, click Finish.

2.5 — What each connection field means

These five fields confuse almost everyone the first time. Here's what each one actually is:

Field What It Means Typical Value
Host Which computer the database lives on. localhost means "this very laptop." localhost
Port Which numbered "door" on that computer to knock on. Each database type has a standard door number. 5432 PostgreSQL
3306 MySQL
Database One server can host many databases. This is the name of the specific one you want. app_db
Username Your database login name. This is separate from your computer login. postgres
Password Your database password. Provided by your instructor or set in the project files

Where do I find these values? For this course they will usually be listed in the project's .env file, the docker-compose.yml file, or the project README. Look for lines containing DB_HOST, DB_PORT, DB_USER, or DATABASE_URL.

2.6 — Your first query

Once connected, expand your database in the left sidebar until you see Schemas → public → Tables. Double-click any table to view its contents.

To run your own query, open a SQL editor (SQL Editor → New SQL Script) and try:

-- Show me the first 10 rows of the users table SELECT * FROM users LIMIT 10;

Press Ctrl + Enter (Windows) or Cmd + Enter (Mac) to run it. Results appear in a grid below.

Two safety rules

  1. Never share your database credentials. Don't paste them into Discord, a public GitHub repo, or a screenshot. Treat them like your bank PIN.
  2. Be very careful with DELETE and UPDATE. Running DELETE FROM users; without a WHERE clause erases every single user. There is no undo button.

Step 3 — Install Postman (for Testing APIs)

3.1 — What is an API?

API stands for Application Programming Interface. Ignore the jargon — here's what it really is: an API is the set of addresses your application listens on, so other programs can ask it for things.

The restaurant analogy:

  • You (the client) sit at a table. You can't walk into the kitchen.
  • The menu lists what you're allowed to order — that's the API documentation.
  • The waiter takes your order to the kitchen — that's the API request.
  • The kitchen (the server + database) prepares it and the waiter brings back your food — that's the API response.

You never need to know how the kitchen works. You just need to know what to order and what comes back. That's exactly how APIs work.

3.2 — What is Postman, and why do we use it?

Postman is a free app that lets you send requests to an API and see exactly what comes back — without writing a single line of code and without needing a finished website.

Here's the problem it solves. Imagine your team is building a login feature. The backend developer finishes the login API on Monday, but the front-end login page won't be ready until Friday. How do you test the API? You can't — there are no buttons to click.

Postman is those buttons. You type the address, hit Send, and see the response instantly.

Specific reasons we use it in this course:

  • ✓Test the backend before the front end exists. No waiting on teammates.
  • ✓Isolate bugs. If the page is broken but Postman shows correct data, the bug is in the front end — not the server. This cuts debugging time enormously.
  • ✓See the real error. A browser might just show "something went wrong." Postman shows you the exact status code and error message.
  • ✓Test edge cases easily. What if the email field is blank? What if the password is 500 characters? Just edit and resend.
  • ✓Save and share your tests. Postman "Collections" let you save every request and share the whole set with your group.

3.3 — Install Postman

Step 3.3a — Download

Go to https://www.postman.com/downloads/ and download the free desktop app for your operating system.

Step 3.3b — Install and sign in

Run the installer. Postman will ask you to create a free account. You can use your student email. There is a small "Continue without an account" link if you prefer — but signing in lets you sync your saved requests across devices, which is genuinely useful.

Step 3.3c — Send your very first request

We'll use a free public practice API so you can confirm Postman works before touching the class project.

  1. Click the + button to open a new request tab.
  2. Leave the method dropdown on GET.
  3. Paste this into the URL bar: https://jsonplaceholder.typicode.com/users/1
  4. Click the blue Send button.

What success looks like

The bottom panel fills with data like this, and you'll see a green 200 OK near the top right:

{ "id": 1, "name": "Leanne Graham", "username": "Bret", "email": "Sincere@april.biz" }

That format is called JSON — it's how APIs send data. It's just labels and values inside curly braces.

3.4 — The parts of a request

Part What It Does Restaurant Equivalent
URL The address you're sending the request to Which restaurant, and which table
Method What kind of action you want Ordering vs. paying vs. cancelling
Headers Extra info, like your login token or data format Showing your ID or stating an allergy
Body The actual data you're sending (only for POST/PUT) The details of your order
Response What the server sends back to you The food that arrives

3.5 — The four methods you'll use constantly

Method Purpose Example
GET Read data. Never changes anything. Load the list of students
POST Create something new. Register a new account
PUT / PATCH Update something that already exists. Change your email address
DELETE Remove something. Delete a post

3.6 — Testing your own project's API

Once your project is running locally, your API lives at http://localhost:3000 (the port number may differ — check your project README).

Example A — Fetch all users (GET)

Method: GET URL: http://localhost:3000/api/users

Nothing else to fill in. Just hit Send.

Example B — Create a user (POST)

This one needs a body. In Postman click the Body tab, select raw, then choose JSON from the dropdown on the right.

Method: POST URL: http://localhost:3000/api/users Body (raw, JSON): { "name": "Ada Lovelace", "email": "ada@example.com", "password": "SuperSecret123" }

Hit Send, then switch to DBeaver and run SELECT * FROM users;. Seeing Ada appear in the table is the moment it all clicks.

3.7 — Reading status codes

Every response includes a three-digit number. Learn these five and you'll diagnose most problems instantly:

Code Meaning What To Do
200 / 201 Success Nothing. It worked.
400 Bad Request — your data was wrong or malformed Check your JSON body for typos or missing fields
401 / 403 Not logged in / not allowed You need to send an auth token in the Headers
404 Not Found — that address doesn't exist Check the URL spelling and the port number
500 Server crashed The bug is in your backend code — read the terminal logs

Step 4 — Understand and Install Docker

4.1 — What does Docker actually mean?

Docker packages an application together with everything it needs to run — the code, the correct version of Node.js, the database, the settings, even a mini operating system — into one sealed unit called a container.

That container then runs identically on any computer that has Docker installed. Your Mac, your classmate's Windows laptop, and the production server in a data center all run the exact same thing.

The shipping container analogy (this is literally where the name comes from):

Before standardized shipping containers, moving goods overseas was chaos — barrels, crates, and sacks all had to be loaded by hand and everything was handled differently.

Then someone invented the metal shipping container. Now it doesn't matter whether it holds bananas or car parts — every crane, truck, and ship handles it the same way. Docker did this for software. The server doesn't care what's inside your container; it just runs it.

4.2 — Why do we use Docker in this course?

  • ✓It kills "but it works on my machine." This is the most common and most frustrating problem in software teams. One person has Node 18, another has Node 22, a third is on Windows — and the code breaks for reasons nobody can reproduce. Docker makes everyone's setup byte-for-byte identical.
  • ✓One command instead of twenty. Without Docker you'd manually install a database server, create users, create tables, configure ports, and set environment variables. With Docker you type docker compose up and it's all done.
  • ✓It keeps your laptop clean. The database runs inside a container, not installed on your actual system. Done with the course? Delete the container and every trace is gone.
  • ✓You can break things safely. Corrupt your database while experimenting? Destroy the container, run one command, get a fresh one in seconds.
  • ✓It's an industry standard. Docker appears in a huge share of developer job postings. Learning it here is directly career-relevant.

4.3 — The four words you need to know

Term What It Is Baking Analogy
Dockerfile A text file listing the steps to build your app's environment The written recipe
Image The finished, packaged result of following that file A frozen ready-to-bake cake
Container A running, live copy of an image The cake, baked and on the table
Docker Compose A tool that starts several containers at once and wires them together Running the whole bakery, not just one oven

The key distinction: An image is stored on disk and does nothing. A container is that image actually running. One image can create many containers, the same way one recipe can bake many cakes.

4.4 — What our project's setup looks like

Our project uses Docker Compose to run several pieces side by side:

Container 1: Node.js web application -> port 3000 Container 2: PostgreSQL database -> port 5432 Container 3: Redis cache (optional) -> port 6379 All three run on a private network and can talk to each other.

Because they share that private network, your app can reach the database using the simple name db instead of an IP address. You'll see that name in the project's config files.

4.5 — Install Docker Desktop

Step 4.5a — Download

Go to https://www.docker.com/products/docker-desktop/

On Mac, pick the build matching your chip (Apple Silicon or Intel). On Windows, Docker needs a feature called WSL 2 — the installer will offer to set this up for you, so just say yes to its prompts.

Step 4.5b — Install, then LAUNCH the app

Run the installer, then actually open Docker Desktop and leave it running. Wait until the whale icon in your menu bar (Mac) or system tray (Windows) stops animating. Docker commands only work while Docker Desktop is running — this trips up nearly everyone at least once.

Step 4.5c — Verify

docker --version docker compose version

Both should print version numbers.

4.6 — The five Docker commands you'll actually use

# Start everything defined in docker-compose.yml docker compose up # Same, but run in the background so you get your terminal back docker compose up -d # See which containers are currently running docker ps # Read the logs (this is where error messages appear) docker compose logs -f # Stop everything docker compose down

Careful: docker compose down -v adds a -v that also deletes all your database data. That's useful when you want a clean slate, but it is permanent. Know which one you're typing.

Step 5 — Set Up GitHub Copilot CLI

5.1 — What is GitHub Copilot CLI?

You may have heard of GitHub Copilot as the tool that autocompletes code inside an editor. Copilot CLI is different and more powerful. It's an AI agent that runs in your terminal, can read the files in your project, run commands, and make edits — while explaining each step to you.

You describe a goal in plain English. Copilot figures out the steps, shows you what it wants to do, and asks your permission before changing anything or running a command.

Why this matters for you: You get the project running and learn how it works at the same time. Instead of blindly copying commands from a README, you can ask "what does this command do and why?" and get a real answer tied to your actual code.

5.2 — Before you install

  • ✓Node.js installed (Step 1) — version 22 or newer
  • ✓A GitHub account
  • ✓An active Copilot subscription

Students get Copilot free. Apply for the GitHub Student Developer Pack at education.github.com/pack using your university email. Approval usually takes a few minutes to a couple of days — apply now so you're not blocked later.

5.3 — Install it

Step 5.3a — Install via npm

Remember npm from Step 1? Here's your first real use of it:

npm install -g @github/copilot

The -g means "global" — install it once for the whole computer, not just one project folder.

Step 5.3b — Start it

Navigate into your project folder first, then launch:

cd path/to/your/project copilot

Being inside the project folder matters — that's how Copilot can see your files.

Step 5.3c — Log in

The first time it runs, type this at the Copilot prompt:

/login

It will display a code and open your browser. Paste the code, approve access, and return to the terminal.

Useful built-in commands once you're inside Copilot:

  • /help — list everything you can do
  • /clear — wipe the conversation and start fresh
  • /exit — quit back to your normal terminal

Alternative: the older gh copilot extension

You may find tutorials referencing a different, older tool. It only suggests and explains single commands — it cannot read your project or edit files. If you want it as well:

gh extension install github/gh-copilot gh copilot suggest "find and kill the process using port 3000" gh copilot explain "docker compose up -d"

For this course, use the copilot command from Step 5.3a. The older one is optional.

5.4 — How to actually work with it

Copilot works in a loop: you describe a goal → it proposes a plan → you approve → it acts → it reports back.

When it wants to run a command or edit a file, it pauses and asks. Read what it's proposing before you say yes. That pause is not an annoyance — it's your chance to learn what the command does and to catch mistakes.

Academic integrity — read this carefully

Using Copilot is encouraged in this course. Submitting code you cannot explain is not.

You may be asked in class to walk through any part of your submission. If Copilot writes something and you don't understand it, the fix is simple and takes ten seconds: ask it "explain what you just wrote, line by line, as if I'm new to this." Do that every time.

5.5 — What makes a good prompt?

The quality of the answer depends almost entirely on the quality of the question. Compare:

Weak Prompt Strong Prompt Why It's Better
"fix my code" "Running npm start gives ECONNREFUSED on port 5432. Find the cause and explain it before fixing." Gives the exact error and asks for understanding first
"add login" "Add a POST /api/login route that checks email and password against the users table and returns a JWT. Follow the patterns already used in this project." Specifies the route, behavior, and existing conventions
"what is this" "Explain what server.js does, in order, assuming I've never used Express." Names the file and states your knowledge level

A reliable formula:

[What I'm trying to do] + [What's happening instead] + [What I already tried] + [Explain it to me at my level]

5.7 — Do and don't

Do

  • Paste the complete error message, not a summary of it
  • Say you're a beginner — it genuinely adjusts its explanations
  • Ask "why" after it does something, every time
  • Read each proposed command before approving it
  • Use /clear when switching to an unrelated task

Don't

  • Approve commands you don't understand — ask first, it's free
  • Paste real passwords, API keys, or personal data into the chat
  • Assume it's always right — AI confidently makes mistakes
  • Let it run destructive commands (rm -rf, DROP TABLE) without fully understanding them
  • Submit work you can't explain out loud

Troubleshooting

"command not found" after installing something

Cause: Your terminal loaded its settings before the tool was installed.
Fix: Fully quit the terminal application and reopen it. If that fails, restart your computer. This resolves it the vast majority of the time.

"EACCES: permission denied" when running npm install -g

Cause: npm is trying to write to a protected system folder.
Fix: Do not use sudo — it causes worse problems later. Instead, point npm at a folder you own:

mkdir -p ~/.npm-global npm config set prefix ~/.npm-global echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.zshrc source ~/.zshrc

Then run your npm install -g command again.

"Cannot connect to the Docker daemon"

Cause: Docker Desktop isn't running.
Fix: Open the Docker Desktop application and wait for the whale icon to go steady. Installing Docker is not the same as running it.

"Port 3000 is already in use"

Cause: An old copy of your app is still running in the background.
Fix (Mac/Linux):

# See what is using the port lsof -i :3000 # Stop it (replace 1234 with the PID from the output above) kill -9 1234

DBeaver says "Connection refused"

Work through these in order:

  1. Is the database actually running? Run docker ps and confirm you see a database container.
  2. Is the port right? PostgreSQL uses 5432, MySQL uses 3306.
  3. Is the host localhost? Note that inside Docker the app uses the service name (like db), but DBeaver on your laptop must use localhost. This catches a lot of people.
  4. Double-check the username and password against the project's .env or docker-compose.yml.

Postman says "Could not send request"

Cause: Nothing is listening at that address.
Fix: Confirm your app is actually running, check for typos in the URL, and make sure you used http:// and not https:// for localhost.
